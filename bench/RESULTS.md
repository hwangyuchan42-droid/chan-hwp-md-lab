# HWP·HWPX → Markdown 첫 속도 시험

2026-11-22~23 · Windows 한 대에서 3개 비교 도구와 unhwp DLL 기반 배치 실험기를 측정했다. 실험의 판정 단위는 **문단 순서와 표의 행·열이 정답과 일치하는 Markdown 파일**이다. [재현 명령](README.md) · [전체 수치](results/summary.md)

## 1,000개 혼합 배치

## 형식에 따라 달라지는 결과

| 단독 작업군 | 전부 통과한 가장 빠른 비교 도구 | DLL 실험기, 작업자 4개 | 통과/회 |
|---|---:|---:|---:|
| HWP 본문·표 24개 | unhwp CLI 0.760초 | 0.257초 | 24/24 |
| HWPX 본문·표 24개 | hwp2md 0.084초 | 0.244초 | 24/24 |
| HWP 500문단 × 8개 | hwp2md 0.101초 | 0.351초 | 8/8 |
| HWPX 500문단 × 8개 | hwp2md 0.075초 | 0.448초 | 8/8 |

[검증됨] HWP 본문·표 24개에서는 실험기가 가장 빠른 동등 품질 비교기보다 5회 모두 빨랐다. HWPX 24개와 500문단 문서의 두 형식에서는 hwp2md가 매회 앞섰다. 따라서 두 형식의 모든 작업군에서 우세하다는 판정 기준은 충족하지 못했다. [형식별 원자료](results/2026-11-22.jsonl) · [회차별 순위 확인](../checks/benchmark-evidence.txt)

[검증됨] hwp2md는 HWP 본문·표 배치를 0.137초에 마쳤고 24개 파일을 모두 생성했다. 통과한 파일은 본문 12개였다. 표에서는 세 번째 행의 품명·수량·단위가 따로 떨어진 문단이 되었고, 마지막 행 수량 칸이 비었다는 정보도 사라졌다. 같은 표의 HWPX는 행·열과 빈 칸을 보존했다. 여러 도구의 Markdown 구분선 길이나 공백은 달라도 같은 표로 해석되면 통과시켰다. [표본과 정답](corpus.py) · [형식별 원자료](results/2026-11-22.jsonl)

## 측정 조건

- Windows 11 Home 26H2, 논리 CPU 16개, RAM 15.32 GiB, 균형 조정 전원 구성. 산출물은 로컬 NVMe의 임시 폴더에 썼다. 시험 간 OS 파일 캐시는 초기화하지 않았다. CPU·메모리 별도 상한은 적용하지 않았다.
- 고유 입력은 본문형·단순 표형·500문단형을 HWP 5와 HWPX로 각각 저장한 6개다. 크기는 7,532~17,920바이트다. 1천 개 묶음은 짧은 본문과 표 4개 파일을 각각 250개로 복제한 9,587,000바이트(9.14 MiB)다. 변환기가 실행될 때마다 빈 출력 폴더에 모든 결과를 새로 썼다. [입력 해시](fixtures/manifest.json)
- unhwp 0.24.0 CLI는 단일 입력 명령을 파일마다 호출했다. hwp2md 0.5.0은 폴더 일괄 명령을 사용했다. kordoc 4.25.3은 파일 목록을 한 번에 주고 작업자 1·4개, GFM 표, 이미지 끔으로 비교했다. DLL 실험기는 unhwp 0.24.0을 한 프로세스에 한 번만 로드하고 파일 단위로 병렬화했다. 전체 빌드·버전·호출 옵션을 고정했다. [재현 절차](README.md) · [비교 명령](baseline.py)
- 매번 폴더 탐색 직전부터 마지막 결과 파일을 닫고 변환 프로세스가 종료될 때까지 경과 시간을 쟀다. 도구 시작과 저장 시간이 포함된다. 원본 복제, 출력 검수, 실험 원장의 사후 기록은 시간에서 뺐다. 전원 상실까지 견디는 디스크 동기화와 제품용 재개 로그는 시험 범위 밖이다.
- 작업군마다 메모리 관측 1회를 먼저 진행하고 실행 순서를 회전해 별도 5회를 측정했다. 속도는 중앙값과 범위다. 메모리는 약 20ms마다 관측한 변환 프로세스 트리의 RSS 합계 중 최댓값으로, 짧은 피크를 놓치거나 공유 페이지를 중복해 셀 수 있다. [측정·검수 코드](baseline.py)
- 매 출력의 바이트를 읽어 UTF-8 Markdown 문단·표 구조를 자동 대조했다. 같은 입력 종류와 같은 출력 SHA-256의 검수 판정만 재사용했다. 표 앞뒤 문단, 행·열, 빈 칸, 한글·숫자·단위를 포함했다. 정답은 생성 코드에 작성했고 독립된 사람 검수는 0건이다. 입력과 출력에 그림, OCR, 제목, 목록, 각주, 병합 셀은 없다.
- 첫 실행의 형식별 4개 작업군은 완료됐다. 혼합 작업군은 첫 메모리 계측 도중 중단되어 그 작업군의 관측값 전체를 제외했다. 동일한 도구·입력 해시로 두 번째 실행에서 혼합 작업군 전부를 다시 측정했다. [첫 실행](results/2026-11-22.jsonl) · [혼합 재실행](results/2026-11-23-mixed.jsonl)

## 검증 범위

[확정] 실험기는 한 폴더의 입력을 처리하는 PHASE 1 코드다. 대규모 실문서의 품질·속도와 실제 사용자의 성공률은 아직 판정할 수 없다. 비교기의 병렬도도 이번에 명시한 설정에서만 비교했다. 500문단 시험은 압축된 파일 크기가 작아 대용량 바이트 처리 시험으로 확대 해석할 수 없다.

[가설] 다음 검증은 한/글에서 직접 저장한 독립 표본으로 수행한다. 직접 만든 HWP는 python-hwpx의 실험적 HWP 쓰기 경로를 거쳤다. 복수 구역·병합 셀·제목·목록을 포함한 문서를 사람이 대조하고, 후보 선택에 쓰지 않은 묶음에서 처리량을 다시 측정한 뒤 제품 엔진을 정한다.
